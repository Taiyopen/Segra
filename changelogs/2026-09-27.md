## 02:32 — 換片後單軌聲音不再斷掉

### 總體
單軌影片的聲音被接到 Segra 自己的播放後，`<video>` 就不能再接第二次。換片或移到待剪輯時，清理把 AudioContext 關掉，下一次又因為已經接過而直接跳過，這支影片之後沒有聲音。現在同一顆元素一直沿用原本的接線，離開剪輯頁才關掉。聲音 WebSocket 也改成把當時那條連線傳進處理函式，避免兩條連線擠在一起。

### 檔案
- `Frontend/src/Hooks/useNativeElementAudio.ts`：換片只重掛播放事件，不再關掉已接到元素上的聲音
- `Frontend/src/Services/nativeAudioSink.ts`：每條 sink 各自記是否在送音，連線關閉時不清掉下一條
- `Backend/App/AudioStreamServer.cs`：handler 抓住當下接受的 socket，不讀後來被換掉的欄位
- `changelogs/2026-09-27.md`：記錄這次修改

### 更動
- 單軌影片換下一部、或移到待剪輯後，聲音還在
- 多軌播放時，單軌那條不再把靜音資料送進同一條串流
- 新的聲音連線不會和上一條搶同一個 handler
- 沒改槽 0 主畫面解析度，也沒改準備刪除的搬移

## 03:43 — 本機 WebSocket 只收自己前端的連線

### 總體
狀態推送用的 `ws://localhost:44030` 原本不看連線來源，任何網頁都能連上、拿到含登入 token 的設定，還能送指令，例如讓 `OpenInBrowser` 啟動本機程式。現在只接受 localhost 來源，這條連線也只回心跳；真正的指令本來就走 Photino，使用者操作不受影響。

### 檔案
- `Backend/App/MessageService.cs`：44030 檢查 Origin、入站只處理 `ping`、`OpenInBrowser` 只開 http/https
- `Backend/App/AudioStreamServer.cs`：44031 聲音串流也檢查 Origin，避免外部網頁踢掉正常連線
- `changelogs/2026-09-27.md`：記錄這次修改

### 更動
- 非 localhost 來源的 WebSocket 握手回 403
- 44030 收到 `ping` 以外的訊息只記長度並忽略，不再先把原文寫進 log
- `OpenInBrowser` 遇到非網址（例如本機 exe 路徑）拒絕並記 warning
- 沒動 localStorage 快取 token 的問題；沒處理 Linux TFM 既有的編譯錯誤
