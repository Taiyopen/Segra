## 01:31 — Stream Deck 插件：用本機連線直接控制 Segra（Claude）

### 總體
新增 Stream Deck 插件，有四顆按鍵：開始／停止錄影、存重播、加書籤、常駐重播緩衝開關。插件透過本機連線（localhost:2222）送指令給 Segra，不是模擬按鍵，所以 F8～F11 熱鍵全部關掉也照樣能用。按鍵每秒更新一次狀態：錄影中變紅、常駐緩衝開著時亮起、Segra 沒開時顯示「離線」。

### 檔案
- `Backend/Api/ControlApi.cs`：新檔，控制入口（`GET /api/control/status`、`POST /api/control/{動作}`），直接呼叫 Segra 介面按鈕用的同一套程式
- `Backend/Api/ContentServer.cs`：把 `/api/control` 轉給 `ControlApi`
- `Segra.Tests/ControlApiTests.cs`：測試控制入口會擋掉沒帶標頭、以及從瀏覽器網頁來的請求
- `Segra.csproj`：C# 建置排除 `StreamDeck\`，避免去掃插件的 node_modules
- `.gitignore`：忽略插件打包輸出 `StreamDeck/dist/`
- `StreamDeck/package.json`、`package-lock.json`、`tsconfig.json`、`rollup.config.mjs`：插件專案設定，照官方 CLI 範本改寫
- `StreamDeck/src/plugin.ts`、`src/segra.ts`、`src/actions/*.ts`：插件程式，負責呼叫 Segra、每秒同步按鍵狀態
- `StreamDeck/com.taiyopen.segra.sdPlugin/manifest.json`、`imgs/**`：插件描述檔、按鍵圖示；插件圖示用 Segra 的 logo 縮放

### 更動
- 安全：必須帶 `X-Segra-Control` 標頭，只要帶了 Origin 就拒絕。瀏覽器網頁送不了這種標頭（要先過預檢，Segra 不回應），因此網頁沒辦法控制錄影
- 書籤、存重播走 `RecordingHotkeyActions`（Segra 介面按鈕用的那套，支援雙槽、會回報成功與否）；錄影開關、常駐緩衝開關的邏輯跟 `MessageService` 裡的同名指令一致
- 沒動熱鍵檔 `KeybindCaptureService.cs`（原本打算把 `HandleKeybindAction` 改成 internal，改用介面按鈕那套後就不需要了）
- 插件用 SDK v2 + Node 20，最低需求 Stream Deck 7.0（v3 要 7.1，使用者裝的是 7.0.3）
- `streamdeck link` 開發模式下，Windows 的 Node 無法透過捷徑建立 logs 資料夾，插件啟動會以 code 1 結束。改成在 rollup 建置時先把資料夾建好
- 沒做 F11 預覽切換；插件沒包進 Segra 安裝檔

- `changelogs/2026-09-28.md`：記錄本次修正

### 更動
- 開錄、最小化主視窗（按 X 縮到系統匣）時，PiP 保持原位；只是還原最小化、置頂、顯示

## 02:39 — 超過 100% 的音量設定真的生效（Claude）

### 總體
麥克風、桌面聲音設 500%、每款遊戲音量覆寫設 200%，實際上都只錄到 100%：ObsKit 的 `Volume` 設定會把數值限制在 0～1。改成換算成 dB 後用 `VolumeDb` 設定，沒有這個上限。重開後 PiP 混音面板顯示麥克風 500%／484%，實測麥克風音量從 -68 dB 升到 -53 dB（約 +14 dB，符合 5 倍）。

### 檔案
- `Backend/Recorder/OBSService.StartRecording.cs`：新增 `SetSourceVolume`，麥克風、桌面聲音、遊戲擷取三處改用它設定音量
- `changelogs/2026-09-28.md`：記錄這次改動

### 更動
- 音量設定超過 100% 的使用者，改完後錄到的聲音會明顯變大，需要重新調整
- 設定頁滑桿範圍、設定檔數值都沒動
